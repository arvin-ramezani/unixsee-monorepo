# Tooling, types, AI-agent docs, and upgrades

## Version-matched docs

Next.js packages include documentation matching the installed version at:

```text
node_modules/next/dist/docs/
```

Agents must read the relevant local docs before changing Next.js code.

A ready-to-copy repository rule is available at `templates/AGENTS.nextjs.md`.

## Type generation

Use:

```powershell
pnpm exec next typegen
```

This generates route-aware TypeScript helpers without a full production build.

Prefer `PageProps`, `LayoutProps`, `RouteContext`, and typed `<Link href>` when `typedRoutes` is enabled.

Do not hand-maintain types already generated by Next.js.

## Turbopack

Turbopack is the default for development and production builds in Next.js 16.

Normal scripts:

```json
{
  "scripts": {
    "dev": "next dev",
    "build": "next build",
    "start": "next start"
  }
}
```

Use top-level Turbopack configuration:

```tsx
import type { NextConfig } from "next"

const nextConfig: NextConfig = {
  turbopack: {},
}

export default nextConfig
```

Use Webpack only for a confirmed incompatibility:

```powershell
pnpm exec next build --webpack
```

## Debugging

Where supported:

```powershell
pnpm exec next dev --inspect
```

For bundle analysis in supported Next.js 16.1+ projects:

```powershell
pnpm exec next experimental-analyze
```

Treat analyzer output as diagnostic, not as a reason for speculative rewrites.

## Upgrade workflow

1. Commit or preserve a clean working state.
2. Inspect current versions and compatibility constraints.
3. Read the target upgrade guide.
4. Run the official upgrade command or codemod.
5. Review generated changes.
6. Run `next typegen`.
7. Run type checking and ESLint.
8. Run focused tests.
9. Run a production build.
10. Test routing, Proxy, images, Server Functions, caching, and deployment.

PowerShell:

```powershell
pnpm dlx @next/codemod@canary upgrade latest
```

Do not run broad upgrades during an unrelated feature task.

## Removed and stale patterns

Flag these in Next.js 16+ App Router code:

- `middleware.ts` for new code when `proxy.ts` is available
- `next/router` inside App Router code
- Synchronous access to async request APIs
- Unnecessary `--turbopack` flags
- `experimental.turbopack` instead of top-level `turbopack`
- `next lint`
- `next/legacy/image`
- `images.domains`
- Experimental PPR flags replaced by Cache Components
- Calling internal Route Handlers from Server Components
- Broad `"use client"` boundaries
- Treating Server Functions as trusted internal calls
